# PerAnt 0.0.1 真实模型实测修复版

版本：`0.0.1+2010`，2026-11-16。

## 版本号重新计算

版本号自本版起从 **0.0.1** 重新计算。此前的 0.6～0.9 是旧编号下的开发预览，相关记录、截图和已发布的 `v0.9.0-preview` 保留为历史，不改写编号。

重新编号的原因：旧编号走到 0.9 时，核心链路还没有用真实模型服务跑通过，实测中多个主要功能不可用，数字和实际成熟度不符。

Android 内部构建号（versionCode）不跟着归零，继续递增到 **2010**。系统只允许构建号更高的包覆盖安装，归零会导致装过 0.9.0（2009）的设备无法升级，只能卸载并丢失数据。

## 为什么会有这一版

0.9.0 发布前没有连接过真实模型服务。本版第一次用真实 DeepSeek API（`deepseek-chat`，Chat Completions）在 Android 模拟器上按用户流程逐项操作，发现并修复了下面的问题。

| 实测现象 | 原因 | 处理 |
| --- | --- | --- |
| 在输入框里交代任务，模型回答“我来做”，然后什么都没发生，任务却显示已完成 | 自己输入的文字默认按普通聊天发送，不带任何工具，也没有告诉模型这一点；勾选“允许模型操作容器电脑”的入口藏在授权弹层里，记住聊天授权后弹层不再出现，入口随之消失 | 普通聊天附带一条固定说明，模型会如实说明这条消息没有电脑权限并指出入口；输入框旁新增“用电脑做这件事”按钮，任何时候都能对当前文字发起电脑任务，仍逐次确认授权 |
| 模型操作桌面时反复点不中图标，12 轮用完仍未打开终端 | 截图以低清晰度发送，模型按自己缩小后的图片回报坐标，与实际像素相差约一倍 | 截图改为高清晰度；发给模型的副本叠加带像素数字的红色标尺，并明确坐标约定。查看器和记录里仍是真实画面 |
| 模型滚动网页后看到一片空白，找不到内容 | 原生截图没有按滚动位置平移画布，滚动后的内容画到了位图之外 | 截图前按滚动偏移平移 |
| 模型浏览长网页时一屏只有几行字 | 隐藏浏览器按 1024×640 横屏、手机像素密度渲染 | 无查看器时改用 1000×1200 的竖向画面 |
| 模型在网页里上下乱滚，找不到页面顶部或底部 | 工具说明没有写明滚动量的正负方向；重新打开已打开的网址时页面停在上次滚动的位置 | 写明正值向下、负值向上及一屏的大致幅度；每次导航先回到顶部；每张网页截图的回执都报告当前滚动位置、页面总高以及是否已到顶部或底部 |
| 稍多几步的桌面或网页任务总是撞上 12 轮上限 | 每次输入前都要单独花一轮截图 | 每次输入的回执直接附带约一秒后的新截图和新的观察编号，可连续操作 |
| 桌面开着时让模型写文件，文件工具和命令都报占用，任务失败 | 模型不知道该怎么办，先试命令行，再用文字问用户 | 明确要求模型直接调用 `desktop_stop`，由应用弹出确认；确认后继续写文件 |
| 上一条里任务虽然最终完成，仍显示“执行失败” | 只要有一步失败，任务就不能标记完成 | 失败的步骤若被之后相同的操作成功重做，任务按完成记录，并注明经过；其余情况仍算失败 |
| “保存网页文字”第一次总是提示“网页已经变化”，再点一次才成功 | 点保存时界面插入的“正在保存”提示行改变了网页视图大小，原生层把尺寸变化当成页面变化，拒绝了正在进行的读取 | 保存进度改为盖在页面上方显示，保存期间上方的提示行保持不变 |
| 在浏览器地址栏输入新网址，文字插进了旧网址中间 | 进入地址栏时没有选中原有内容 | 进入地址栏即全选 |
| 点“测试已保存的连接”后看不到结果 | 结果显示在按钮下方，手机上在屏幕之外 | 结果同时用提示条弹出，并移到按钮正下方 |

## 实测记录

设备：Android 16 / API 36 ARM64 模拟器，4 GB 内存、4 核、宿主 GPU。服务：DeepSeek `deepseek-chat`，Chat Completions。

网页任务和一次桌面任务在最终构建上完成。写文件、手动浏览器、本地整理和终端各项在此前一两轮构建上完成，其后只改了浏览器工具的说明和滚动位置回执，没有重跑；例外已在表中注明。

| 项目 | 结果 |
| --- | --- |
| 从 0.9.0 覆盖安装 | 通过，配置、Key 和会话保留 |
| 配置 DeepSeek 并测试连接 | 通过，提示条显示结果 |
| 普通聊天 | 通过；同一会话的第二轮在 0.9.0 包和网关实测中验证，最终构建上只发了单轮 |
| 普通聊天里要求执行操作 | 模型说明没有电脑权限，并指向电脑按钮 |
| 预设“一起写个小脚本”：写入 `hello.py`、确认命令、运行并读取输出 | 在 0.9.0 包上通过；本版重测了写文件和确认弹层，没有重跑命令执行 |
| 模型启动桌面，双击打开终端，输入命令并读出输出 | 3 次运行均通过，6～7 轮；其中一次第一下双击没有打开，模型看截图后重试成功 |
| 模型打开 example.com，找到页面底部的链接并点击，保存落地页 | 最终构建上连续 5 次全部通过，每次都是打开、截图、滚动一次、点击、保存 5 步。加入滚动位置回执之前的各轮构建合计 7 次只通过 4 次，失败时模型按记忆认定链接在页面顶部，反复滚动直到轮次用完 |
| 桌面运行时让模型写文件 | 3 次运行均通过：模型请求关闭桌面，确认后写入，任务显示已完成 |
| 手动浏览器：输入网址、打开公网 HTTPS 页面、保存文字 | 首次保存成功，连续第二次保存成功 |
| 本地“整理一段文字”、打开文档编辑器 | 通过 |
| 手动终端：列出工作区、`python3 --version` | 通过，能看到上述任务生成的全部文件 |
| 任务进行中模拟器进程崩溃后重开应用 | 任务显示“已中断”，没有自动重放 |

自动检查：格式与静态分析通过，Python 14、Dart 292（另 2 项可选截图跳过）、Android JVM 72。网关层另有 `packages/perant_gateway/tool/live_check.dart`，可对真实服务检查连接、两轮对话和工具往返，本次 5 项通过。

## 仍未验证或已知的问题

- **只用了一家服务、一个模型。** 其他七家预设、Responses 协议都没有用真实 Key 跑过。
- **只在模拟器上测过。** 没有实体手机数据；3 GB / 2 核 / 软件渲染配置下 Linux 首次安装曾超时，本版没有重测，也没有处理。
- **网页任务只验证了一个页面上的一种操作。** 同一任务最终连续 5 次成功，但没有测过登录页、弹窗、表单输入、多标签或脚本很重的站点；换一个页面或换一个模型，成功率需要重新测。
- **点击精度有限。** 加标尺后模型在测试中都点中了图标和链接，但误差仍有十几到二十像素，小按钮可能点偏。桌面任务只跑了三次，其中一次需要重试，不能代表稳定成功率。
- **12 轮 / 24 次工具的上限没有变。** 需要十步以上的图形操作（例如用 Writer 写完并另存为文档）仍可能做不完，本版没有测模型操作 LibreOffice。
- **桌面运行期间，文件页和模型的文件工具不可用**，只能先关闭桌面，未保存的图形应用内容会丢失。这是现有的互斥设计，本版只改善了模型的应对方式。
- **本地文字整理会给句号等标点加反斜杠。** Markdown 源码里显示为 `\.`，预览正常。脚本属于固定的运行资源，本版没有改动。
- 系统中文输入法没有测：测试用 adb 注入英文，中文任务只走了预设按钮。
- 本地小模型、iOS 运行时、长期后台、检索与记忆、DOCX / PDF 导出仍未实现，见[任务规划书](../../TASK_PLAN.md)。
