# Linux 电脑的易用性设计

版本：0.7 原型，2026-11-13。范围为聊天入口、Linux 桌面会话、原生浏览器和手机查看器，保持 PerAnt 对话优先与按需显示。0.7 设备验收结果单独记录，文末 0.6 证据仅代表历史交付。

文中标注的本地开发证据和构建产物（如 `artifacts/`、`.tooling/` 与生成的运行资源）未随本次源码发布；源码预览的验证范围以文内记录为准。

## 现状与处理

| 现状 | 影响 | 处理 |
| --- | --- | --- |
| 1024×640 横屏桌面缩进约390dp宽的竖屏，画面高度约244dp | 大量空白、文字小、难以触控 | 首次查看按手机方向选择720×1080或1120×700；保留已有会话，不因旋转重启 |
| 只有窗口和小按钮，启动应用依赖命令或隐藏菜单 | 用户难以找到入口和切换窗口 | 真正的 Linux 开始菜单、底部任务栏、桌面图标与文件管理器 |
| 查看器只有无标签图标，回车藏在滚动末端 | 难猜功能，文字输入步骤多 | 文件、终端、应用、窗口、键盘五个中文入口，键盘面板完整显示常用按键 |
| 触屏长按若先发送左键释放，在单击打开的文件管理器中会先打开文件 | 右键落在错误窗口 | 触屏区分点按、长按和拖动；鼠标保留即时按下/释放 |
| 横屏软键盘挤压剩余高度 | 可能溢出并挡住发送或回车 | 高度不足时让输入面板滚动，提供明确的收起键盘入口 |

## 对话入口

应用外层参考 [nanoMuse 官方界面](https://nanomuse.cn/assets/chat-approval-zh.webp)与[开源实现](https://github.com/nano-muse/nanoMuse)：白底、居中头像与状态、黑色用户消息、浅灰助手消息、紧凑胶囊输入、58dp 浮动导航。保留 PerAnt 自有标识与交互，不复用对方品牌图案。

空会话显示可点击的“模型的电脑”状态卡，底部增加独立电脑入口；模型与容器协作选项位于输入区旁。卡片只读取会话状态，不请求截图、连接显示或启动桌面；键盘弹出时收起卡片与底部导航，将空间留给对话。实际工具执行状态继续在对话中呈现。

## 桌面习惯

采用类 Windows 的开始菜单、任务栏和最大化窗口操作。使用成熟的 Xfce 核心会话：Xfwm4 管理窗口、Xfce Panel 提供开始菜单和任务栏、Xfdesktop 提供桌面，Thunar、Xfce Terminal、Mousepad 和 Settings Manager 分别处理文件、命令、文本与设置。全部为真实 Linux 应用。开始菜单和桌面固定入口使用中文标签，文件工作区始终为 `/workspace`。不使用 Apple 或 Microsoft 商标素材。

浅色中性表面、一个蓝色强调、清晰文件夹/终端/编辑器图标。避免透明模糊与常驻合成器。Linux 像素、系统字体和手机逻辑像素分别记录，不能将 native 84px 点击区域直接称为84dp。手机查看器的主要按钮至少48×60dp，常用按键至少44dp高。

浏览器与办公软件通过“应用”面板集中呈现，底部仍保留五个可读的按钮：文件、终端、应用、窗口、键盘。选择面板只显示入口，选择具体应用才启动；窄屏和横屏可滚动，不将所有应用挤进常驻工具栏。Linux 任务栏固定文件、终端、文档三项，开始菜单另外列出表格、演示文稿、文本编辑器与设置。

浏览器使用 Android 原生 WebView，提供手机原生尺寸的地址栏、前进与后退。可从聊天更多菜单直接打开，无需先启动 Linux；从电脑打开时暂停 Linux 查看并释放其帧图像，返回后恢复同一桌面窗口。用户和模型共用一个页面，隐藏时不连续截图，临时截图按需生成。保留浏览器页面并不意味着其 JavaScript、网络或渲染进程内存归零。

默认手机竖屏720×1080；横屏/较宽屏1120×700。显示设置另外提供1280×800工作区。已有桌面始终保留原尺寸；切换尺寸展示具体关闭窗口的确认，不自动重放未保存编辑。全屏用于增加查看面积，缩放模式与操作模式有明确文字状态。

## 共享操作

手机快捷按钮发送同一桌面的真实RFB按键：

| 入口 | Linux快捷键 |
| --- | --- |
| 开始菜单 | Super+Space |
| 文件 | Super+E |
| 文档 | Super+W |
| 表格 | Super+C |
| 演示文稿 | Super+P |
| 终端 | Ctrl+Alt+T |
| 编辑器 | Super+N |
| 窗口 | Alt+Tab |
| 显示桌面 | Super+D |
| 最大化当前窗口 | Alt+F10 |
| 系统设置 | Super+I |

模型取得输入控制权时手动输入禁用，用户可停止接管。模型仍从真实截图观察同一桌面，坐标对应实际远端像素。退出查看或切后台，持续RFB连接、Dart帧和Flutter图像句柄释放；模型截图仍为临时单帧连接。保留窗口的Xserver和Linux应用仍占内存。

## 验收方式

用原生 Android APK验证开始菜单、文件入口、窗口切换、真实GUI键入生成文件和后台释放；不用网页作为移动端证据。离线回归检查手机/横屏布局、最小触控范围、真实按键、点按/长按/拖动、键盘挤压和原有双图像句柄释放。最终运行截图、APK哈希和已通过范围随交付记录保存，不能将测试fixture称为模拟器真实桌面。

0.7.0 的 API37 ARM64 设备用例已通过 28/28：原生浏览器 5、Writer 2、桌面 3、既有回归 18。浏览器覆盖真实 JavaScript、触控、同页隐藏/重挂、过期观察、取消与错误恢复；Writer 覆盖 ODT／DOCX 的实际 GUI 保存及重开编辑。桌面生命周期用例通过 binding 注入，不代表系统后台调度；Calc／Impress 尚未做相同文件往返。对应本轮验收（`artifacts/android-desktop-v07/VERIFICATION.md`）与结构化记录（`artifacts/android-desktop-v07/integration-results.json`）可复核。

最终 0.7.0 APK 的人工入口检查也已通过：聊天更多菜单打开原生浏览器并显示外网 HTTPS 正文；电脑应用面板打开真实 Writer，再查看浏览器并返回，原有 Writer 窗口和 Xvnc／Xfce／Writer 进程保持不变。见浏览器截图（`artifacts/android-desktop-v07/browser-apk-api37.png`）、文档截图（`artifacts/android-desktop-v07/writer-apk-api37.png`）及人工记录（`artifacts/android-desktop-v07/manual-apk-check.json`）。此次为应用内切换，不扩展为系统后台、锁屏或低内存真机验收。

0.6.0交付APK已在API37 ARM64模拟器人工打开聊天电脑卡、文件快捷入口，并在Android最近任务切换后恢复同一Thunar窗口。实际聊天截图（`artifacts/android-desktop-v06/chat-apk-api37.png`）、文件窗口截图（`artifacts/android-desktop-v06/desktop-apk-api37.png`）及人工记录（`artifacts/android-desktop-v06/manual-apk-check.json`）可复核；短时任务切换不代表长时后台调度、锁屏或4GB真机已验收。
