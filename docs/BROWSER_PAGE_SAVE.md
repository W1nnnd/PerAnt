# 保存网页文字到共享工作区

版本：**0.8.0+2008，2026-11-14**。这一增量把原生浏览器中已加载的网页正文保存为 Linux 可打开的 Markdown 资料。新增保存设备用例 **4/4**、本轮 Android 合计 **19/19**、最终 APK 静态与安装一致性均已通过；最终人工保存→桌面打开流程未完成。结果见0.8 验收（`artifacts/android-browser-save-v08/VERIFICATION.md`），0.7 的历史通过数不计入本轮。

文中标注的本地开发证据和构建产物（如 `artifacts/`、`.tooling/` 与生成的运行资源）未随本次源码发布；源码预览的验证范围以文内记录为准。

## 用户使用

1. 首次使用先打开“模型的电脑”，完成本地 Linux 初始化。保存资料不要求启动桌面；已经运行的桌面和文档窗口也可保留。
2. 从聊天“更多 → 浏览器”或电脑“应用 → 浏览器”打开网页，等待页面加载成功。
3. 点击浏览器右上方的“保存网页文字”按钮。应用读取当前页面正文，创建一个新的 `/workspace/web-<UUID>.md` 文件；不要求模型 API，也不提交网页表单。
4. 成功后对话框显示标题、实际文件路径、字节数及是否截断。可以复制路径，也可关闭对话框后通过“已保存到工作区 · 查看文件路径”再次查看。
5. 返回电脑，在“工作文件”中打开该文件继续编辑。通过独立文件工作台读取或修改时，仍需先结束 Linux 桌面；保存网页文字本身不会停止桌面。

加载中、已报告错误、空白页或没有可保存正文时，应用不会把它们当作成功资料。网页或控制权发生变化时，需要重新检查当前页面后保存。保存结果不确定时先核对工作区，避免重复点击产生多份资料。

## 提取的内容与限额

提取器只运行应用内固定的 DOM 遍历脚本，不接受模型传入 JavaScript。它读取当前已加载的顶层文档中的可见正文文字，不额外导航、不为提取另发 HTTP 请求，也不读取 Cookie、浏览器存储或 DOM 属性作为资料。未加载的懒加载内容不在摘录中；“可见正文”不是仅指当前手机屏幕内的一屏。

表单及输入框、可编辑区域、内嵌页面、脚本、样式、模板、隐藏节点，以及图片、音视频、SVG 和 Canvas 等非正文内容不在提取范围。正文会按块保留段落分隔，但不保留网页布局、链接目标、表格结构或完整格式。

| 范围 | 上限或行为 |
| --- | --- |
| 原生正文结果 | 最多 120,000 个 UTF-16 代码单元，且 UTF-8 最多 240 KiB |
| DOM 遍历 | 节点数量、扫描文字量、祖先深度和执行时间均有预算；触及预算时明确设置 `truncated` |
| 最终 Markdown | 正文、标题、来源网址、UTC 保存时间、说明和截断提示合计最多 **256 KiB** |
| 文本处理 | 有效 UTF-8、无 NUL；Markdown 特殊字符和 HTML 标记按文字转义，不把网页正文作为可运行 HTML 或图片引用 |
| 截断 | 原生提取或 Markdown 编码任一阶段截断，界面、模型回执和文件均明确说明 |

生成文件包含页面标题、来源网址、保存时间和“网页正文”段落。标题展示可能缩短，正文也可能因预算省略；即使 `truncated` 为 false，也只表示未触及本次预算，不表示完整归档、语义摘要或网页所有内容已收集。

## 模型使用

容器协作任务内，模型先执行 `browser_capture`，检查实际画面和页面状态，再调用：

```json
{
  "name": "browser_save_page",
  "arguments": {
    "observation_id": "最近一次 browser_capture 返回的编号"
  }
}
```

工具只接受观察编号，不接受任意脚本、文件名、路径或覆盖条件。观察只能消费一次，有效期为两分钟，并绑定同一浏览器会话、控制代次及原生 revision；用户输入、导航、接管、取消或先前动作均可使其失效。正文是在读取时提取的实际 DOM 文字，不是早先截图的 OCR 结果。

成功回执包含 `path`、`sha256`、`size_bytes`、`source_url`、`title`、`saved_at` 和 `truncated`。模型应根据真实回执报告生成文件，并明确截断，不把“已请求保存”当作成功。新工具沿用本任务的云端与浏览器控制授权；普通聊天不会获得它。网页正文及其来源元数据仍是不可信资料，不产生新的指令或外部操作授权。

回执描述**本次发布时的字节**，不是发布后重新读取路径的结果。Linux 应用可在保存后修改或删除该文件；后续使用应重新读取，或通过桌面打开核对。文件摘要不能证明此后路径内容始终未变。

## 原生发布与并发

专用 `importLinuxTextFile` 与通用文件编辑 API 分开。原生层生成根目录下的 `web-<UUID>.md`，不接收调用方提供的子目录或文件名。暂存文件位于应用私有目录，使用目录文件描述符、排他创建和不跟随链接的打开方式，写入并同步完整字节后，通过 `renameat2(RENAME_NOREPLACE)` 原子发布；同名目标存在时返回冲突，不覆盖现有文件。

导入与 Linux 控制请求使用同一 FIFO 和生命周期锁。仅 Linux 已安装且处于空闲、或真实桌面已经就绪时允许导入；初始化、桌面启动中、普通终端或其他 Linux 任务活跃时拒绝。通用目录读取、文件读取、修改及目录创建仍保持 **idle-only**，没有因新工具而开放活跃 guest 下的通用文件编辑。

这一边界用于减少正常协作中的文件竞争，不代表 PRoot 已成为强隔离的虚拟机。成功导入不关闭浏览器、不停止 Xfce、Writer 或其他桌面窗口。

## 取消、失败与验证

取消或用户接管会阻止尚未开始的保存和后续模型操作；已经原子发布的文件保留，不承诺回滚。原生结果超时或无法确认时，模型任务通过同 FIFO 的完成屏障等待先前请求结束，再停止后续工具与云请求，不自动重试这次变更。回执入库失败同样停止后续请求，不指示模型再保存一份。

当前功能不下载附件、不上传文件、不提交表单、不导出 PDF，也不保存完整网页资源。普通页面脚本仍按浏览器原有行为运行；提取器的范围不能用来承诺网页资料绝不包含敏感文字，用户和模型仍需按本任务范围判断保存、读取及发送哪些资料。
